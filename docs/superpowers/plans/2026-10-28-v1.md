# v1 文档与工程基线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 严格兼容 NestJS v1 的文档 CRUD，完成 PostgreSQL/MongoDB 闭环与可恢复写入，并建立 Python 工程门禁。

**Architecture:** FastAPI 负责协议适配；documents 的用例与纯规则依赖 DocumentStore 协议；双库适配器负责仓储、锁、操作日志和补偿。应用生命周期管理客户端，测试注入明确依赖，业务不绑定框架。

**Tech Stack:** Python 3.12、uv、FastAPI/Pydantic、SQLAlchemy Async/asyncpg、Alembic、PyMongo Async、HTTPX/pytest、Ruff、mypy strict。

**Spec:** [v1 规格](../../versions/v1/spec.md)、[v1 契约](../../contracts/v1.md)；规则入口 [AGENTS.md](../../../AGENTS.md)。

## Global Constraints

- Python 3.12；uv 管理并锁定依赖。
- 生产代码覆盖率至少 85%；单生产文件最多 300 物理行（含注释空行），目标 200。
- 当前 v1 已从 main 派生；本版验收后合并 main，v2 再从更新后的 main 派生。
- 五个 `/documents` 接口、camelCase JSON、字符串 ID、原错误及 PostgreSQL/MongoDB 职责保持兼容。
- NestJS 源码固定 `f9dfce20ffe798dc35ede0a74219f06bf3d6980f`；未完成运行采集不能宣称兼容。
- 不触碰旧 volumes；不加入 v2 上传或 v7 认证；未执行命令不得记通过。
- 每版交付必须逐项向用户汇报完成的需求、实现方式、验证证据和未完成事项，并在验收记录中保存同一份对照。

## Review Focus

- 缺失/null/字符串数字/未知字段必须匹配 Nest 校验，不返回默认 422；由 Task 1、6 的契约用例覆盖。
- Mongo 成功但 SQL commit 失败、提交成功但回包异常、PG 持续不可用、补偿失败和中断重启必须恢复一致；由 Task 4、5 故障注入覆盖。
- 并发修改或恢复不能覆盖较新内容、重复增版本或复活删除；由 Task 5 的真实双库并发测试覆盖。
- 超大 ID、UTF-16 长度/截断、空白和 CJK 字数不能因 Python 语义变化漂移；由 Task 1、2、6 覆盖。
- 本地真实 `.env`、旧数据库或错误构建产物不能污染测试与基线；由 Task 1、3、7 环境校验覆盖。
