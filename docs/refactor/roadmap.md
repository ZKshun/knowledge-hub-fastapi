# 版本路线与验收出口

每版包含前序已合并能力。开发顺序是“最新 main → vN → 验收 → main”；本版尚未合并时不能开始下一个版本。vN 不用于改变 URL 前缀。

表中内容为范围和完成要求，**不是完成清单**；实际状态见 [status.md](status.md)。

| 版本 | 功能范围 | 本版新增验收出口 |
| --- | --- | --- |
| v1 | 工程门禁、文档 CRUD、PostgreSQL/MongoDB、雪花 ID、分页筛选、软删除 | 创建→查询→修改→软删除；字符串 ID、camelCase、默认值、双库补偿、数据库迁移和旧接口契约通过 |
| v2 | PDF/DOCX/PPTX/XLSX/TXT 解析、上传、RustFS | 上传→Markdown 草稿→详情；附件/图片地址、类型、大小、空文件和解析失败可验证 |
| v3 | RabbitMQ、分块、Embedding、ES 向量、异步 Worker | 触发→Outbox→消费→向量块；重复、乱序、超时、重试、死信和恢复可追踪 |
| v4 | ES 文档级全文索引 | 新增/更新→全文索引；归档删除清理；失败不伪装成功且可重建 |
| v5 | LLM 实体关系抽取、Neo4j 建图 | 文档→抽取→节点/关系/来源；重建与删除幂等、抽取失败可恢复 |
| v6 | 草稿、待审核、发布、归档状态机及审核 | 提交→通过/驳回→索引变化；待审不可编辑、审核重复提交、状态转换完整覆盖 |
| v7 | JWT 注册、登录、刷新、基础角色鉴权 | 登录→访问→刷新→退出；无效/过期令牌、角色边界匹配原版 |
| v8 | 用户角色管理、激活邮件、找回密码、Redis | 注册激活→登录、验证码→重置；过期、重复使用、密码与资料访问控制 |
| v9 | 权限、角色授权、用户直授权、团队树/成员 | 授权→生效→撤销；角色与用户权限组合、团队层级、成员增删边界 |
| v10 | 全文搜索和图谱读取 API | 发布→索引→检索；排序、高亮、分页、节点边查询及错误契约 |
| v11 | BM25/向量/RRF/Rerank、RAG 检索和非流式问答 | 固定样本召回→重排→回答引用；库空不编造、模型与重排失败路径 |
| v12 | 图谱全景、节点/边/搜索、统计和前端图谱契约 | 全景过滤、节点边引用闭合、限制参数和前端数据结构 |
| v13 | 会话和消息持久化、重命名、删除 | 创建→对话落库→历史→重命名→删除；归属隔离和顺序稳定 |
| v14 | 流式问答与联网搜索 | AI SDK 消息事件/响应头/终止事件、引用与思考、断连取消及失败；联网来源可追溯 |
| v15 | 文档/全文/向量/图谱统一可见性 | 公开、本人、团队、管理员的权限矩阵；权限变化后缓存/索引/引用不泄漏 |
| v16 | Redis 短期记忆、Mem0 长期记忆、指代和检索改写 | 热窗口过期回填、跨会话偏好、会话任务隔离、改写失败回退 |
| v17 | 意图路由、评估、重写再检索、Agentic RAG | 闲聊不检索、内部制度不乱联网、最多两次知识检索、空结果和工具边界 |
| v18 | 知识库与图谱并行检索的 GraphRAG | 并行执行、关系有来源、图谱不冒充原文、两路可见性及失败降级 |
| v19 | Golden Dataset、评测、Langfuse 观测 | 固定数据集回归、指标与链路对应、脱敏、不配置观测时的兼容行为 |
| v20 | MinerU 精确解析、图片抽取和 RustFS URL 替换 | 扫描 PDF/Office/图片→Markdown；轮询超时、ZIP 校验、图片地址和清理 |
| v21 | 分类、版本、评论、点赞、收藏、分享、通知 | 版本恢复与重新索引、互动计数、分享密码/失效/撤销、通知已读和权限 |

## 每版共同交付物

1. `docs/versions/vN/spec.md`：需求、来源提交、边界、接口和本版验收条件。
2. `docs/contracts/vN.md` 与匿名契约夹具：静态推导与运行证据分开标记。
3. `docs/superpowers/plans/<date>-vN.md`：文件职责、签名、测试与执行步骤。
4. 代码、锁文件和所需数据库/索引/MQ 迁移；旧版本回归与本版验证。
5. `docs/versions/vN/acceptance.md`：验收结果、实际命令、失败与未运行项。
6. 更新状态、日志、README；获授权后合并 main，并记录合并提交。

## 贯穿能力的交付节奏

配置、错误适配、日志、生命周期、测试隔离和质量门禁随 v1 建立；跨库恢复从 v1 开始；Outbox 和消费者幂等随 v3 引入；安全能力按 v7/v9/v15 扩展；RAG 固定样本从 v11 建立，完整评测平台随 v19 交付。

如果原版行为与业务闭环有冲突，先记录缺陷及兼容影响。内部可靠性改进可以实施并验证；对外行为变化必须按兼容策略处理，不能顺手修正。
