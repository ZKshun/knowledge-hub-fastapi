# 严格兼容策略

本次迁移保持原接口和多数据库职责。每个 vN 对齐旧后端 vN 的固定文件树；最终 v21 功能是目标，不能用 v21 的校验/权限要求覆盖早期版本行为。

## HTTP 与 JSON

必须记录并验证：method、path、query、header、Content-Type、multipart 字段、请求字段/别名/默认值、null 与字段缺失、校验行为、HTTP 状态、响应字段/类型、分页和排序、错误 body、鉴权与所有权规则。

- 保持 `/documents`、`/auth`、`/ai/chat/stream` 等原始后端路径。前端 `/api` 来自代理重写，不给后端硬加统一前缀。
- NestJS POST 默认 201 等行为必须在运行基线中确认，FastAPI 默认值不能直接替代。
- 原版校验通常返回 400 和 `{statusCode,message,error}`，其中 `message` 可为数组；不能把 FastAPI 默认 422/detail 暴露给现有客户端。
- 外部 ID 是字符串；响应与 Mongo 文档既有 camelCase 字段不改名；分页保持 `{items,total,page,pageSize}`，不统一换成另一种封装。
- 原版 enum 数值、空字符串、null、布尔/数字转换和时间序列化以对应版本契约为准。

## 流式协议（v14 起）

前端使用 AI SDK `DefaultChatTransport`。必须采集并复现实际响应头、UI 消息流起止、文本增量、reasoning、工具事件、自定义 `data-*` 事件、来源、会话事件、错误、取消和结束标记。

仅用 `text/event-stream`、只发送纯 token、只验证 HTTP 200，都不能证明兼容。以真实前端协议消费测试及脱敏事件夹具验证；不要求模型每个 token 的自然语言完全一致。

## 存储与异步

| 系统 | 保留契约 | 可做的内部增强 |
| --- | --- | --- |
| PostgreSQL | 原表/列名、ID、状态、原有数据含义 | 添加式迁移、跨库操作日志、Outbox、任务表和索引 |
| MongoDB | document_content 字段、ObjectId 与 content_id/documentId 关联、版本和软删除 | 幂等写入、可恢复操作标识、一致性核对 |
| Elasticsearch | kh_document/kh_chunk 的文档/分块职责、可见性、召回字段 | 有版本的 mapping 和索引重建；不自动覆盖现有索引 |
| Neo4j | 实体关系及来源、查询结果与访问范围 | 约束、幂等、孤儿清理和重建 |
| Redis | 验证码生命周期和会话热窗口/回填语义 | 隔离测试命名空间、明确 TTL 和撤销 |
| RabbitMQ | 对应版消息类型、队列和处理语义 | Outbox、重试/死信、版本/任务标识、消费幂等 |
| RustFS | S3 兼容、原文件/图片及可访问 URL | 对象清理与隔离前缀、失败补偿 |

“保留架构”不代表新旧服务同时双写同一个生产库。测试使用独立数据库、索引、队列和 bucket；数据迁移/切流在实际需要时单独规划。添加内部消息字段时，兼容原消息解析；若未来并行运行旧消费者，必须先验证拓扑和混合版本策略，不能假定兼容。

保留既有环境变量名、单位和默认语义。Python 属性可转换为 snake_case，但部署不能被迫同时重命名全部配置。新增端口、数据库名和隔离前缀可以增加设置，不覆盖已有运行配置。

## 证据与契约提取 SOP

1. 记录 source SHA、版本、配置模式、数据库初始状态和前端 SHA。
2. 从 controller/DTO/entity/service 提取静态契约，标为“源码推导”。
3. 在隔离环境运行固定原版本，对匿名样例记录响应、错误、存储副作用与消息；补齐“运行验证”标记。
4. 用同一输入运行 Python，实现逐字段比较和语义断言。
5. 仅归一化明确非确定性字段：生成 ID、ObjectId、时刻、模型自然语言；必须保留类型、格式、跨对象关联和先后约束，不能整块忽略响应或事件。
6. 验证列表/详情/索引/引用/权限的副作用；异步轮询使用超时和状态断言，不能固定 sleep 后就算成功。
7. 将证据放在版本验收记录。存在未判定差异、缺少必需的运行证据或关键测试 skip，则版本不能验收。

夹具采用合成内容，无账号密钥和个人资料。真实契约夹具和“预期推导”分开，不使用新服务自己输出的快照自证旧版兼容。

## 差异和缺陷

错误状态码、严格校验、撤销令牌或参数限制看似更好，也可能是兼容变化。发现旧版缺陷，记录输入、原行为、影响与建议；保持正常既定契约的内部可靠性修复可实施，改变外部行为或安全语义需用户明确决定。

私密文档的隔离与索引撤销必须贯穿所有读取面；不要把原系统“假设未发布文档不在索引”当成新系统可以不校验最新状态的理由。
